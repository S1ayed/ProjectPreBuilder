# 登录与权限规划

## 1. 方案确定

- 后端：Node.js + Express
- 数据库：SQLite
- 登录：JWT + httpOnly Cookie
- 角色：admin、editor、viewer

## 2. 数据库结构（MVP）

```sql
create table if not exists users (
  id integer primary key autoincrement,
  username varchar(64) not null unique,
  password_hash varchar(255) not null,
  role varchar(16) not null default 'viewer',
  created_at datetime not null default current_timestamp
);

create trigger if not exists users_role_check
before insert on users
for each row
when new.role not in ('admin', 'editor', 'viewer')
begin
  select raise(abort, 'invalid role');
end;
```

## 3. 数据库与权限模型细化

### 3.1 权限模型选择

- 当前采用最简单 RBAC：用户 -> 单一角色 -> 固定权限集合。
- 角色枚举：`admin`、`editor`、`viewer`。
- 不支持多角色与资源级权限（后续可扩展）。

### 3.2 角色权限定义（建议）

| 角色 | 权限范围 | 说明 |
| --- | --- | --- |
| admin | 所有 | 管理员，可管理用户与全量资源 |
| editor | 读写 | 可创建/编辑/删除自身可见资源 |
| viewer | 只读 | 仅查看 |

### 3.3 未来可扩展结构（可选）

当需要多角色或细粒度权限时，建议引入如下表结构：

```sql
create table if not exists roles (
  id bigserial primary key,
  name varchar(32) not null unique,
  description varchar(255) not null default ''
);

create table if not exists permissions (
  id bigserial primary key,
  code varchar(64) not null unique,
  description varchar(255) not null default ''
);

create table if not exists role_permissions (
  role_id bigint not null references roles(id) on delete cascade,
  permission_id bigint not null references permissions(id) on delete cascade,
  primary key (role_id, permission_id)
);

create table if not exists user_roles (
  user_id bigint not null references users(id) on delete cascade,
  role_id bigint not null references roles(id) on delete cascade,
  primary key (user_id, role_id)
);
```

### 3.4 权限检查方式

- MVP 阶段：直接基于 `users.role` 判断。
- 扩展阶段：通过 `user_roles` + `role_permissions` 查询出权限集合并缓存到 JWT 中。
